# 人狼オンライン

GM不要でオンライン人狼が遊べるWebアプリ。ホストがルームを作り、URLを共有するだけで4〜16人が各自の端末から参加できます。役職の配布・夜の処理・時間管理・投票集計・勝敗判定はすべてシステムが自動で行います。

議論は Discord などの通話で行う前提です（アプリ内チャットはありません）。

## 動かす

```bash
cd werewolf && npm install && npm start
```

`http://localhost:3000` を開いてルームを作成し、表示されるURLを参加者に共有します。

初めての人向けのルール説明は、トップの「📖 ルールと遊び方」とゲーム画面右上の「？」からいつでも開けます（勝利条件・1日の流れ・役職一覧・細かい裁定）。役職一覧はサーバーの役職定義から生成しているので、`server/game.js` の `ROLES` を変えれば説明も自動的に追従します。

```bash
npm test
```

## 設計の要点：サーバー権威（Server-Authoritative）

人狼で最も守るべきは**役職の秘匿**です。そのためこのアプリでは、ゲームの真実をすべてサーバー（`server/rooms.js` のメモリ上）に置き、クライアントには「**そのプレイヤーが知ってよい情報だけ**」を組み立てて送ります。

```
Room（サーバーの真実）
  └─ viewFor(room, playerId) ──▶ そのプレイヤー専用のビュー
       ├─ 自分の役職            : 常に
       ├─ 仲間の人狼            : 自分が人狼のときだけ
       ├─ 占い / 霊媒の結果      : 本人宛のログだけ
       ├─ 他人の役職            : ゲーム終了後のみ全公開
       └─ 誰が投票済みか         : 公開（投票先は集計後に公開）
```

**Room オブジェクトを丸ごと broadcast しない**。これがこのコードベースの唯一絶対の規約です。`test/secrecy.test.js` が実際にサーバーを起動し、全プレイヤーが受信したペイロードを1件残らず検査してこれを保証しています。

夜の解決・投票集計・勝敗判定もすべてサーバーで行うため、ホストを含め誰も不正できません。タイマーもサーバー時刻が基準で、クライアントは `phaseEndsAt` との差分を描画するだけです。

### ファイル構成

| ファイル | 役割 |
|---|---|
| `server/game.js` | 副作用のない純粋ロジック（役職配布・夜の解決・投票集計・勝敗判定）。テストはここに集中 |
| `server/rooms.js` | ルームの状態、フェーズ遷移、タイマー、`viewFor`（秘匿の要） |
| `server/index.js` | HTTP静的配信 + Socket.IO の配線のみ。ゲームの判断は書かない |
| `public/index.html` | クライアント（単一ファイル・ビルド不要） |
| `tools/bots.js` | 手動テスト用の自動プレイボット |

## フェーズ遷移

```
lobby ──▶ roleReveal ──▶ night ──▶ morning ──▶ discussion ──▶ vote ──▶ execution ──┐
                            ▲                                                       │
                            └───────────────────────────────────────────────────────┘
                     （襲撃後と処刑後に毎回、勝敗判定 → 決着していれば gameOver）
```

- `night` は全員の行動が揃うか制限時間で終了。占い結果だけは選択した瞬間に本人へ返します。
- `discussion` は生存者が減るほど自動的に短くなります（初期人数に対する按分・下限90秒）。
- ホストは各フェーズを手動でスキップできます。

## 役職

| 役職 | 陣営 | 能力 |
|---|---|---|
| 市民 | 村人 | なし |
| 占い師 | 村人 | 夜に1人を占い、人狼か人間かを即座に知る |
| 霊媒師 | 村人 | 前日に処刑された人が人狼だったかを夜に知る |
| 騎士 | 村人 | 夜に自分以外の1人を護衛し、襲撃から守る |
| 人狼 | 人狼 | 夜に1人を襲撃。仲間の人狼が分かる |
| 狂人 | 人狼 | 能力なし。占うと「人間」。人数は人間側、勝利判定は人狼陣営 |

占い師・霊媒師・騎士は各1人までです。妖狐は未実装。

### CPU（人数合わせ）

人が集まらないとき、ホストがロビーからCPUを追加できます。**CPUは既定で市民に固定**され、役職抽選から外れます。

これは実装の手抜きではなく設計です。人狼は会話のゲームなので、喋れないCPUが人狼や占い師を引くとゲームが成立しません（CPUが人狼なら即バレ、占い師なら結果を公表できず死に役）。CPUを市民固定にすると、意味のある役職は必ず人間に配られ、CPUは**生存者の頭数**としてだけ機能します。3人しか集まらないときにCPUを2体足して5人にすれば、人狼1・占い師1・狂人1を人間3人で分け合う成立したゲームになります。

- CPUは夜に何もせず、投票にランダム参加します（`botsVote` で棄権に変更可）
- `botsAreVillagersOnly` をOFFにするとCPUにも役職が配られますが、まともなゲームにはなりません
- CPUはホストになれません。人間が最低1人必要です
- CPUを市民固定にする場合、市民の枠がCPUの数以上ないと開始できません

### 確定しているルール

- **同票**: ランダムに1人を処刑（無投票は棄権。全員棄権なら処刑なし）
- **勝敗**: 人狼0人で村人陣営の勝ち / 人狼 ≧ 人間で人狼陣営の勝ち（狂人は人間として数える）
- **人狼が複数**: 襲撃先は人狼全員の多数決。同数・無投票はランダム
- **初日の襲撃**: ホストが設定でON/OFFできる（既定はON）

## 切断・再接続

プレイヤーIDと再接続トークンを localStorage に保存し、リロードや通信断からそのまま復帰します。トークンは本人以外に送信されません。

- 切断してもゲームは進行します（制限時間で自動的に次のフェーズへ）
- 夜と投票は、切断中の人がいても即座には終わりません（一瞬の通信断でフェーズが飛ぶのを防ぐため）
- ホストが落ちても20秒間は権限を保持し、戻ってこなければ次の人へ移譲。ルーム作成者が戻ってきたらホストが返ります
- ルームは2時間で自動的に破棄されます

## デプロイ

Node 20+ が動く環境に1プロセス置くだけです。`PORT` 環境変数を見ます。永続化はしておらず、プロセスを再起動すると**進行中のゲームは失われます**。

```bash
PORT=8080 node server/index.js
```

### Render

リポジトリ直下の [`render.yaml`](../render.yaml) がそのまま使えます。Renderのダッシュボードで **New + → Blueprint** からこのリポジトリを選ぶだけです。

無料プランは**15分アクセスがないとスリープ**し、復帰に30秒ほどかかります。スリープするとプロセスが落ちるので進行中のゲームは消えます。遊ぶ前に一度URLを開いて起こしておいてください。

| 設定 | 値 |
|---|---|
| Root Directory | `werewolf` |
| Build Command | `npm ci --omit=dev` |
| Start Command | `node server/index.js` |
| Health Check Path | `/healthz` |

### 外部公開時のガード

公開前提で以下を入れてあります。

- **CORSは同一オリジンのみ**（`cors` を設定していない＝他サイトからソケットを張れない）
- **1接続あたり10秒120イベントで遮断・切断**、ルーム連続作成は20秒のクールダウン
- **ルーム数の上限**（`MAX_ROOMS`、既定300）と、2時間放置での自動破棄
- `maxHttpBufferSize` を8KBに制限、CSP・`X-Frame-Options: DENY` 等のヘッダ
- `SIGTERM` で接続中のプレイヤーに通知してから終了

## 手動テスト

ボットを既存のルームに参加させて1人で通し確認できます。

```bash
node tools/bots.js <ルームID> 5
```
